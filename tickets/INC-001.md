# INC-001: HQ-PC2 has no network access

| Field | Value |
|---|---|
| Area | Access (Layer 1/2) |
| Affected | HQ-PC2 (10.1.10.12, HQ-ACC2 Fa0/1, VLAN 10) |
| Fault time (SRV1) | 2026-11-04 12:08:16 PM |
| Fixed (SRV1) | 2026-11-04 12:14:24 PM |
| Status | Resolved |

## Reported issue

"HQ-PC2 has no network access at all."

## Impact

One user, HQ-PC2, had no connectivity: not to its own gateway, other VLANs, the branch or the internet. No other users were affected: the fault was on HQ-PC2's own access port, which carries no one else's traffic, and no other complaints came in.

## Logs

SRV1, all from 10.1.99.12 (HQ-ACC2):

```
12:08:16.046 PM  %LINK-5-CHANGED: Interface FastEthernet0/1, changed state to administratively down
12:08:16.046 PM  %LINEPROTO-5-UPDOWN: Line protocol on Interface FastEthernet0/1, changed state to down
12:08:18.170 PM  %SYS-5-CONFIG_I: Configured from console by console
```

After the fix, 12:14:24 PM: the same two interface messages with "changed state to up", followed by another `%SYS-5-CONFIG_I`.

## Troubleshooting steps

| # | Command | Result | What it showed / ruled out |
|---|---|---|---|
| 1 | HQ-PC2: `ping 198.51.100.10` | 0/4, timed out | Confirmed the complaint |
| 2 | HQ-PC2: `ipconfig /all` | 10.1.10.12/24, gateway 10.1.10.1, DHCP server 10.1.0.1 | IP settings correct; ruled out addressing and DHCP |
| 3 | HQ-PC2: `ping 10.1.10.1` | 0/4, timed out | Can't reach its own gateway, so the fault is between the PC and HQ-CORE: Layer 1 or 2 |
| 4 | SRV1 SYSLOG | HQ-ACC2 logged Fa0/1 "administratively down" plus a console config change at 12:08 | Fa0/1 is HQ-PC2's port. "Administratively down" means a `shutdown` command, not a cable or hardware fault |

## Root cause

HQ-ACC2 Fa0/1, the access port for HQ-PC2, had been shut down with the `shutdown` command.

## Fix

On HQ-ACC2:

```
configure terminal
interface fa0/1
no shutdown
end
```

## Verification

- HQ-PC2 `ping 10.1.10.1`: 4/4, TTL 255 (gateway reachable)
- HQ-PC2 `ping 198.51.100.10`: 4/4, TTL 125 (internet reachable)
- SRV1: Fa0/1 "changed state to up" from HQ-ACC2 at 12:14:24 PM
- Smoke test, all as expected:
  - HQ-PC1 → 10.1.30.10: replies
  - BR-PC1 → 10.1.30.10: replies
  - HQ-GUEST1 → 198.51.100.10: replies
  - HQ-GUEST1 → 10.1.30.10: blocked ("Destination host unreachable")

## Prevention

- Syslog caught this immediately: an "administratively down" on a user's access port should raise an alert, since only a person can cause it.
- Require a change ticket before shutting down any access port, and label ports in use (for example, `description HQ-PC2`) so nobody shuts the wrong one.
- Restrict who can make configuration changes, and use AAA with per-user accounts so the log shows *who* made the change, not just "console".
