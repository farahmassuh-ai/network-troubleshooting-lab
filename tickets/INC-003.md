# INC-003: Repeated spanning-tree warning between HQ-CORE and HQ-ACC1

| Field | Value |
|---|---|
| Area | Switching (Layer 2, trunk / STP) |
| Affected | Trunk HQ-CORE Gi1/0/2 ↔ HQ-ACC1 Gi0/1 |
| Fault time (SRV1) | 2026-11-04 12:31:51 PM (config change on HQ-CORE) |
| First warning (SRV1) | 2026-11-04 12:41:35 PM |
| Fixed (SRV1) | 2026-11-04 12:43:41 PM |
| Status | Resolved |

## Reported issue

Monitoring alert: "HQ-CORE and HQ-ACC1 keep logging the same warning. Users report no problems."

## Impact

No user impact: Staff, Guest, Server and Management traffic kept working. HQ-ACC1 blocked VLAN 1 on its uplink, and VLAN 30 traffic toward HQ-ACC1 would have landed in the wrong VLAN. Neither VLAN had devices on HQ-ACC1, so nothing visible broke. The risk was latent: any VLAN 30 device later connected to HQ-ACC1 would have failed, and mismatched native VLANs can let traffic leak between VLANs.

## Troubleshooting steps

| # | Command | Result | What it showed / ruled out |
|---|---|---|---|
| 1 | SRV1 SYSLOG | Config change on HQ-CORE at 12:31, then STP "inconsistent peer vlan id 30" and "Blocking Gi0/1 on VLAN0001" from HQ-ACC1, and CDP "NATIVE_VLAN_MISMATCH" from both switches every minute | The two ends of the HQ-CORE–HQ-ACC1 trunk disagree about a VLAN; "peer vlan id 30" points at the native VLAN |
| 2 | Smoke test (users) | All pass | Confirms no user impact; Staff, Guest and Server VLANs unaffected |
| 3 | HQ-CORE: `show interfaces trunk` | Gi1/0/2 **Native vlan 30**; Gi1/0/3 native 1 | Baseline: native 1 on both. HQ-CORE's end of the trunk to HQ-ACC1 was changed |

## Root cause

The native VLAN on HQ-CORE Gi1/0/2 was changed to 30, while HQ-ACC1 Gi0/1 kept native VLAN 1. The native VLAN is the one VLAN a trunk sends untagged, so both ends must agree. CDP reported the mismatch on both switches, and spanning tree detected it from the BPDUs and blocked the inconsistent VLAN on HQ-ACC1's uplink.

## Fix

On HQ-CORE:

```
configure terminal
interface gi1/0/2
switchport trunk native vlan 1
end
```

## Verification

- HQ-CORE `show interfaces trunk`: Native vlan 1 on Gi1/0/2 and Gi1/0/3 (matches baseline)
- SRV1: HQ-ACC1 logged `UNBLOCK_CONSIST_PORT` for VLAN 30 and VLAN 1 at 12:43:41, and the CDP mismatch messages stopped
- Smoke test, all as expected:
  - HQ-PC1 → 10.1.30.10: replies
  - BR-PC1 → 10.1.30.10: replies
  - HQ-GUEST1 → 198.51.100.10: replies
  - HQ-GUEST1 → 10.1.30.10: blocked

## Prevention

- Set the native VLAN explicitly and identically on both ends of every trunk; better still, use a dedicated unused VLAN as native on all trunks.
- Treat severity 0–2 messages on SRV1 as alerts even when users are happy: this fault was invisible except in the logs.
- After any trunk change, check `show interfaces trunk` on both ends against the baseline.
